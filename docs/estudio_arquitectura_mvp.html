Lo que el docente preguntará
  1. Muéstrenme dónde está la clave del modelo. (Si es un archivo del repositorio, integración vale 0.)
  2. ¿Qué pasa si el proveedor devuelve 429? Demuéstrenlo.
  3. ¿Por qué esa temperatura y ese límite de tokens?
  4. ¿Qué aprendieron al comparar los tres prompts?
Errores que cuestan la nota esta semana
  • La clave en el repositorio: integración en 0 y hay que revocarla.
  • El sistema inventa con seguridad: se pierde el nivel esperado.
  • El modelo calcula montos, fechas o prioridades.
  • Todo subido el último día: el historial de Git lo muestra.

      Paso 4

      Decisiones de arquitectura

      Una decisión, un registro corto: contexto, opciones, decisión y consecuencias.

      Cómo escribir un buen ADR

      Paso a paso
      1. Contexto: describan la situación y las fuerzas en tensión (cuota gratuita, tiempo, datos personales, lo que pide el caso). Sin decidir todavía.
      2. Opciones: al menos dos alternativas reales, cada una con una ventaja y una desventaja concreta.
      3. Decisión: en voz activa y con el porqué: «Usaremos X porque…».
      4. Consecuencias: lo que ganan y lo que les cuesta. Si no hay nada negativo, falta pensar más.
      5. Estado: «Aceptado» cuando el grupo lo acordó. Si cambian de idea, escriben un ADR nuevo y este pasa a «Reemplazado».

      Esta semana deben tener aceptados ADR-001 (proveedor y modelo), ADR-002 (workflow o agente) y ADR-003 (claves y datos personales). El ADR-004 es propio de su caso: recomendable, no obligatorio.
